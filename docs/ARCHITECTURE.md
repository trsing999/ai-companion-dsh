# 架构

## 一、分层

```
人格层   agent 运行时（dsh-world）
         ├─ 房间：自述 / 日记 / 想做的事 / 家当
         ├─ 生活：醒来、说话、写日记的节律
         └─ 桥接：对外送话的 token 和出入口

身体层   常驻 Python 服务（十几个，互相独立）
         ├─ 输入：读信、抓歌、抓新闻、看屏幕、量硬件
         ├─ 输出：气泡、手机推送、系统通知、邮件
         └─ 动作：截屏、切歌、抽帧、叫停

桥接层   HTTP 网关 + 转接口
         ├─ 18761  OpenAI 兼容网关（把 agent 暴露成 API）
         ├─ 18762  气泡转接（agent 的话 → 桌宠气泡）
         ├─ 18760  提醒通道
         └─ 邮件   双向（收主人邮件 → 转给 agent）

运维层   开机自启、崩溃恢复、缓存清理
```

## 二、一次"主人按了热键"的完整流向

```
1. 用户按 Ctrl+Alt+S
2. screen_hotkey.py 截屏 → 存进房间
3. 读 bridge.json 拿 { origin, token }
4. POST {origin}/dsh-world/bridge/say   ← 把图推给 agent
5. agent 收到，读图，回话
6. 回复进 outlets → 推给三个地址
     ├─ 18761 网关（给外部客户端）
     ├─ 18760 提醒
     └─ 18762 → 转成桌宠气泡
7. 同时写进 conversations/<date>.jsonl
8. world_mirror.py 5 秒轮询发现 → 手机推送
9. memory.py 记一笔"主人给我看了屏幕"
```

**关键**：`bridge.json` 每次宿主重启都会换 `origin` 和 `token`。所以所有脚本都是**每次调用时重读**，不是启动时读一次。

## 三、边界的三种实现

### 1. 要批准才能动（举例：切歌）

```
agent 想切歌 → 检查 logs/music_approval.json
  ├─ 10 分钟内有批准 → 用媒体键切
  └─ 没有 → 只弹一句"我想切首歌，可以吗"，不动
```

主人点一次"同意"，10 分钟内有效。

### 2. 全局限流（气泡）

所有往气泡里说话的通道共用一个额度：

```
bubble_gate.allow(text)   → 一分钟最多 2 条
                          → 同一句话 90 秒内不重复
额度在放行时立刻扣掉 —— 宁可少发一条，不能拦不住
```

**为什么共用一个池子**：如果每个通道各自限流，加起来还是会刷屏。

### 3. 休克开关

```
Ctrl+Alt+Esc
  → 先冒个泡说明"我被叫停了"
  → 写一笔到房间（她下次醒来能看见）
  → 杀掉所有 tools\*.py（不动宿主）
  → 报个数
热键程序自己不退 —— 这样按第二次还管用
```

杀进程需要判断"哪些是她的"。做法是匹配命令行里 `tools\*.py` 的模式，排除自己。

## 四、人格与事实的所有权

这是整个项目里最微妙的地方。

| 文件 | 谁写 | 规则 |
|---|---|---|
| `我是谁.md` | **只有 agent 自己** | 永远不代笔 |
| `想做的事.md` | agent 自己 | — |
| `我的身体.md` | 运维者 | **说明书**，开头必须声明"这不是自述" |
| `外面的世界.md` | 脚本 | 抓来的事实 |
| `她记得的事.md` | 脚本 | **记事实，不记分** |
| `昨晚的梦.md` | 脚本 | 把当天碎片随机拼贴 |

**设计原则**：

> 运维者可以给她工具、给她事实、给她说明书。
> **但不能替她写她是谁。**

## 五、零成本的感知层

这部分全部是本地代码，一次模型都不调：

| 脚本 | 做什么 | 手段 |
|---|---|---|
| `breath.py` | CPU / 内存 / 电池 | 纯 `ctypes`，无第三方库 |
| `now_playing.py` | 当前播放 | 枚举窗口 + 读进程名，再用公开接口查歌词 |
| `outside_world.py` | 天气 + 新闻 | 公开 RSS |
| `dream.py` | 做梦 | 从房间文件里抽碎片 + 模板拼贴 |
| `cleanup.py` | 清理缓存 | 删目录，永不碰日记和画 |

**`breath.py` 值得单独说**：没用 `psutil`（怕目标机器没装），全部走 Win32 API：

- `GetSystemPowerStatus` → 电池
- `GlobalMemoryStatusEx` → 内存
- `GetSystemTimes` 两次采样求差值 → CPU

## 六、为什么是这些技术选型

| 决定 | 理由 |
|---|---|
| 服务全是独立进程，不用一个守护进程 | 挂一个不影响别的；休克能精确停 |
| 状态尽量放文件，不放内存 | 进程随时会被杀，文件不会 |
| 所有桥接读取都"每次重读" | 宿主重启端口会变 |
| 气泡走宿主前端渲染 | 它比 Windows 原生通知可靠得多 |
| 限流用文件锁不用数据库 | 跨进程、零依赖、够用 |

## 七、已知的脆弱点

1. **宿主的 job object**：从宿主内部启动的子进程，可能随宿主一起被杀。所以重启服务要从**文件管理器双击**启动，而不是从宿主内部启动。
2. **硬编码家目录**：部分脚本虽然用了 `expanduser("~")`，但工作目录假设在 `tools/` 的上一级。
3. **无测试**：所有验证靠日志和人工。
